# ძველი სტატიების შემოტანა და მასობრივი მართვა

**რას აკეთებს:** ძველი პორტალის 122 რეალურ სტატიას გადმოაქვს ახალ ბაზაში,
და აძლევს ადმინისტრატორს ხელსაწყოს, რომ ისინი თანდათან გამოაქვეყნოს.

---

## 1. რა შემოდის და რა არა

ძველ ბაზაში 168 სტატიაა. შემოდის **122** — ID 17-დან 138-მდე:

| შემოდის | არ შემოდის |
|---|---|
| „როუმინგული ტარიფები" | „QA E2E Test Article" |
| „GPON პარამეტრები (Huawei)" | „dasdsa", „ტესტ", „დრაფტ" |
| „მობილური პორტირების პროცედურა" | უსათაურო მონახაზები |

დანარჩენი 46 სატესტო ნაგავია და განზრახ რჩება გარეთ.

სტატიებთან ერთად შემოდის **11 კატეგორია**, **429 სურათი** და **132 ძველი
ვერსია** — ბოლო იმიტომ, რომ სტატია, რომლის ისტორია „იმპორტით" იწყება,
აუდიტისთვის გამოუსადეგარია.

## 2. ყველა სტატია მონახაზად შემოდის

ეს განზრახაა.

122 სტატიის ერთბაშად გამოქვეყნება დამარხავს იმას, რაც ოპერატორმა **მართლა**
უნდა წაიკითხოს. მონახაზი ნიშნავს:

- **ოპერატორი ვერ ხედავს** — ვერც ძებნაში, ვერც სიაში
- **ყველა კონტენტ-ადმინი ხედავს და მართავს**

ანუ ზუსტად ის მდგომარეობა, საიდანაც თანდათან გამოშვება შეიძლება.

## 3. როგორ გაეშვება

```bash
python scripts/import_legacy_content.py
```

ეს **არაფერს წერს** — მხოლოდ გაჩვენებს, რა მოხდებოდა. ნამდვილად შესატანად:

```bash
python scripts/import_legacy_content.py --apply
```

**ორჯერ გაშვება უსაფრთხოა.** მეორე გაშვება არსებულს განაახლებს და არ
გააორმაგებს — თითოეული სტატია ჩაწერილია `legacy_content_imports` ცხრილში
თავისი ძველი ID-ით.

> **მეორე გაშვება არ შეცვლის სტატუსს.** თუ ადმინმა უკვე გამოაქვეყნა ან სხვა
> დეპარტამენტს მიაბა რომელიმე სტატია, ხელახალი იმპორტი მას **უკან არ
> დააბრუნებს** — ტექსტი განახლდება, გადაწყვეტილება დარჩება.

### სად გაეშვება

| გარემო | როგორ |
|---|---|
| ლოკალური | ისე, როგორც ზემოთ |
| UAT / პროდაქშენი | `ORACLE_DB_URL`, `ORACLE_DB_USER`, `ORACLE_DB_PASSWORD` იმ ბაზაზე დააყენე და გაუშვი |

**წინაპირობა:** ბაზაზე მიგრაცია `V47` უნდა იყოს დადებული (backend-ის ერთი
გაშვება საკმარისია) და უნდა არსებობდეს ერთი მოქმედი კონტენტ-ადმინი, რომელსაც
იმპორტი მიეწერება. თუ არ არსებობს, სკრიპტი უარს ამბობს — **მომხმარებელს
თვითონ არ ქმნის**, რადგან იმპორტი, რომელსაც კონტენტის უფლებიანი ანგარიშის
შექმნა შეუძლია, სწორედ ამისთვის გამოდგება.

## 4. მასობრივი მართვის ხელსაწყო

**ადმინი → კონტენტი.** ყოველ სტატიას ახლა უჯრა აქვს მარცხნივ.

მონიშვნისთანავე ზემოთ გამოჩნდება ზოლი:

| ღილაკი | რას აკეთებს |
|---|---|
| **გამოქვეყნება** | ოპერატორები დაინახავენ. კითხავს დადასტურებას |
| **მონახაზიდ** | ისევ იმალება |
| **არქივში** | იმალება, მაგრამ ცალკე მდგომარეობაა |
| **კატეგორიის შეცვლა** | ყველა მონიშნული ერთ კატეგორიაში გადადის |
| **აუდიტორიის შეცვლა** | ყველა მონიშნული ერთ დეპარტამენტს მიება |

დადასტურებას **მხოლოდ გამოქვეყნება** ითხოვს. დამალვა უკან იხსნება ერთი
ღილაკით; გამოქვეყნება კი მასალას 600 ადამიანის წინ დებს.

### სამი რამ, რაც უნდა იცოდე

**უჯრა მხოლოდ სტატიებს აქვს.** სიახლეებსა და ვიდეოებს არა — მასობრივი
ოპერაციები სტატიებისთვისაა, და თუ სიახლის მონიშვნა შეიძლებოდა, სისტემა
გეტყოდა „5-დან 3 განახლდა" ყოველგვარი ახსნის გარეშე.

**შედეგი ყოველთვის ითქმება.** „განახლდა 12 მასალა, 3 გამოტოვებული (უკვე ამ
მდგომარეობაში იყო)". გამოტოვება შეცდომა არ არის — ეს ნორმალურია, როცა
სიაში ისეთი სტატიაა, რომელიც უკვე გამოქვეყნებულია.

**თითოეული სტატია ცალკე აუდიტდება.** არა „50 სტატია დაარქივდა", არამედ 50
ჩანაწერი. შესაბამისობის კითხვა ყოველთვის ერთ სტატიაზეა — *როდის გაქრა ეს
თვალიდან და ვინ გადაწყვიტა* — და ჯგუფური ჩანაწერი ამას ვერ პასუხობს.

## 5. სავალდებულო საკითხავად გადაქცევა

ეს **ჯერ არ არის მასობრივი**. სტატიის სავალდებულოდ დანიშვნა ერთ-ერთია, და
ასეც რჩება — ვადა, დეპარტამენტი და ქვიზი თითოეულზე ცალკე გადაწყვეტილებაა და
ერთი თარიღი ასეულ სტატიაზე გრაფიკი არ არის.

როცა გამოშვების რიტმი დაიდება და გამოჩნდება, რომ მართლა საჭიროა — დაემატება.
