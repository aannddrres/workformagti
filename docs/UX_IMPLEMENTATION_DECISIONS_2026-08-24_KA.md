# UX/უსაფრთხოების გადაწყვეტილებების განხორციელება — 2026-08-24

ეს დოკუმენტი აფიქსირებს 1–154 კითხვაზე დამტკიცებული მიმართულებების იმ ნაწილს,
რომელმაც მიმდინარე Angular/Java პორტალში არქიტექტურული ან UX ცვლილება გამოიწვია.
საწყისი აუდიტის შემდეგ მომხმარებლის პასუხები არის უპირატესი წყარო.

## იდენტობა და წვდომა

- production ავტორიზაცია არის მხოლოდ კომპანიის SSO/AD; AD-ის მიუწვდომლობისას
  წვდომა fail-closed პრინციპით არ გაიცემა;
- ლოკალურ loopback გარემოში დარჩა მხოლოდ პაროლის გარეშე სატესტო პერსონების
  არჩევანი; production-ში ადგილობრივი login და პაროლის reset/create გამორთულია;
- access token ინახება მხოლოდ HttpOnly, SameSite=Strict cookie-ში; Angular იყენებს
  CSRF cookie/header კონტრაქტს და credentialed request-ებს;
- სესია სრულდება 30 წუთის უმოქმედობის ან მაქსიმუმ 8 საათის შემდეგ; 2 წუთით ადრე
  იხსნება სავალდებულო გაფრთხილება. ანგარიშის გვერდიდან სხვა აქტიური სესიების
  გაუქმება შეიძლება;
- მხოლოდ `SYSTEM_ADMIN` ხედავს raw audit log-ს. სისტემური ადმინი ყველა capability-ს
  ფლობს და ბოლო აქტიური სისტემური ადმინის გათიშვა/დაქვეითება შეზღუდულია.

## როლზე მორგებული სამუშაო სივრცეები

- ოპერატორი იწყებს მთავარ გვერდზე, მენეჯერი — გუნდის სტატისტიკაში,
  კონტენტ-ადმინი — საკუთარ ერთიან სამუშაო რიგში, სისტემური ადმინი — მიმოხილვაში;
- მენეჯერის `team_id` არის მისი ერთადერთი ძირითადი გუნდი. დროებითი
  leadership assignment-ები სტატისტიკის selector-ს ემატება, მაგრამ ექსპორტს
  არასოდეს აფართოებს;
- კონტენტ-ადმინის navigation-ში კონტენტის სამუშაო სივრცე ადმინისტრაციული
  ბლოკის ბოლოშია.

## კონტენტის მართვა

- სტატიები, სიახლეები და ვიდეოები ერთ საერთო queue/table-შია, type/status/search
  ფილტრებითა და split create მოქმედებით;
- ფილტრების ტიპი, სტატუსი, ტექსტი და გვერდი URL query პარამეტრებში ინახება;
- სამივე editor სრულეკრანიანია. კონტენტი და სავალდებულო დავალება ერთ backend
  transaction-ში ინახება; სტატიის quiz-იც იმავე transaction-ის ნაწილია;
- დახურვისას შეუნახავი ცვლილება დასტურს ითხოვს; modal/dialog-ები საერთო focus
  trap, Escape და focus-restore კონტრაქტს იყენებს;
- კონტენტი ჯერ არქივდება და შემდეგ გადადის სანაგვეში. წაშლილი სტატიის/თანამშრომლის
  read receipt, view და compliance მტკიცებულებები snapshot-ებით რჩება;
- სტატიებისა და სიახლეების feedback ფუნქცია, endpoint-ები, UI, API კონტრაქტი და
  payload-ები ამოღებულია. მიგრაცია ინახავს მხოლოდ წაშლილი row-ების რაოდენობასა და
  შესრულების დროს, არა feedback-ის შინაარსს.

## ვიზუალური და ტექნიკური საფუძველი

- გამოყენებულია Magti-ის ოფიციალური logo assets და ბრენდის ძირითადი `#ED1B2F`;
- Georgian UI იყენებს პროექტში ლოკალურად ჩადებულ Noto Sans Georgian-ს;
- desktop shell არის 264px sidebar-ით, მცირე ეკრანზე კი overlay navigation-ით;
- route-ები lazy-loaded-ია; 403 და 404 ცალკე მდგომარეობებად ჩანს;
- rich text არის Quill 2-ზე, backend HTML sanitization-ით და frontend DOMPurify-ით;
- production initial bundle-ის კონტროლის ზღვარი არის 700 KB.

## production-ის გარე დამოკიდებულება

კოდში SSO adapter fail-closed-ია, მაგრამ რეალური AD/OIDC/SAML metadata, client
credentials, callback URL-ები და IT ინფრასტრუქტურის კონფიგურაცია ამ repository-ში
ვერ შეიქმნება. ეს რჩება ერთადერთ გარე launch-დამოკიდებულებად და მის გარეშე
production წვდომა განზრახ არ იმუშავებს.
