# პორტალის გაშვება ამ Windows ლეპტოპზე — მფლობელისთვის

ეს არის **ადგილობრივი საცდელი გარემო**, მხოლოდ ამ კომპიუტერზე. Magti-ს თანამშრომლებისთვის მისი გამოქვეყნება არ შეიძლება. IT-ის ჩაბარება იწყება [IT-ის მოკლე გვერდიდან](IT_START_HERE_KA.md).

---

## მომზადება და გაშვება

1. Windows-ზე დააყენეთ და გახსენით **Docker Desktop** (WSL 2 რეჟიმით). დაელოდეთ, სანამ Docker Desktop გაჩვენებთ, რომ engine მუშაობს. მისთვის ხელმისაწვდომი უნდა იყოს **მინიმუმ 6 GB მეხსიერება** და დისკზე საკმარისი თავისუფალი ადგილი Oracle-ის image-ისა და მონაცემებისთვის. Java და Node ამ გზისთვის საჭირო არ არის.
2. გახსენით **PowerShell** პროექტის საქაღალდეში `C:\Projects\Magti base` და გაუშვით:

```powershell
cd 'C:\Projects\Magti base'
docker compose -f docker-compose.local.yml up --build -d
```

3. პირველ გაშვებას **10–15 წუთი** შეიძლება დასჭირდეს. ამ დროს Oracle იწყებს მუშაობას, Java ქმნის/აახლებს სქემას Flyway-ით, ხოლო ერთჯერადი `seed` ამატებს სანახავ კონტენტს. სხვა PowerShell ფანჯარაში შეამოწმეთ:

```powershell
docker compose -f docker-compose.local.yml ps --all
curl.exe -sS http://localhost:8080/api/health
```

გაშვება მზადაა, როცა `oracle` და `backend` არის **healthy**, `frontend` — **Up**, ხოლო ჯანმრთელობის პასუხი შეიცავს `"status":"ok"` და `"database":"ok"`. HTTP კოდის სანახავად გამოიყენეთ `curl.exe -sS -o NUL -w 'HTTP %{http_code}' http://localhost:8080/api/health` — მოსალოდნელია `HTTP 200`. `seed`-ის `Exited (0)` წარმატებული დასრულებაა. თუ 15 წუთში ასე არ არის, გადადით [დიაგნოსტიკის სახელმძღვანელოზე](IT_OPERATIONS_RUNBOOK_KA.md#პრობლემების-მოძიება).

4. Chrome-ში გახსენით **http://localhost:8080**. ლოკალურ შესვლის ეკრანზე „სხვა ანგარიშით შესვლა“ ველში ჩაწერეთ `info@magti.ge` და დააჭირეთ მის გვერდით „შესვლა“-ს — პაროლი არ მოითხოვება. უნდა გამოჩნდეს მთავარი გვერდი, ორი ცოდნის კატეგორია და საცდელი სიახლეები. „ცოდნის ბაზაში“ აირჩიეთ „ინტერნეტი და ქსელი“ და გახსენით ერთ-ერთი სტატია. ადმინისტრატორის ეკრანის შესამოწმებლად იგივე ველში გამოიყენეთ `admin@magti.ge`. ეს მხოლოდ ადგილობრივი ტესტია.
5. გასაჩერებლად გაუშვით `docker compose -f docker-compose.local.yml stop`. ხელახლა გასაშვებად — `docker compose -f docker-compose.local.yml start`; შემდეგ კვლავ შეამოწმეთ `ps --all` და ჯანმრთელობის პასუხი. **Oracle-ის მონაცემები რჩება** სახელდებულ Docker volume-ში. `down`-იც volume-ს ტოვებს, მაგრამ ჩვეულებრივი გაჩერებისთვის `stop` უფრო მარტივია.

> **მონაცემების დაცვა:** არ წაშალოთ Docker volume და არ გამოიყენოთ `down -v`, `volume rm`, `system prune --volumes` ან `run-local.sh --clean`. ეს ადგილობრივ ბაზას წაშლის. თუ შეცდომაა, ჯერ [უსაფრთხო შემოწმებები](IT_OPERATIONS_RUNBOOK_KA.md#უსაფრთხო-დიაგნოსტიკური-ბრძანებები-windows-powershell) შეასრულეთ.

## მნიშვნელოვანი საზღვარი

ლოკალური Compose ჩართულია `APP_ENV=development` და `ALLOW_DEV_LOGIN=true` პარამეტრებით: საცდელ ანგარიშებზე, ადმინისტრატორის ჩათვლით, backend ნებისმიერ პაროლს იღებს, ხოლო ლოკალური ეკრანი პაროლს საერთოდ არ ითხოვს. პორტი მხოლოდ `127.0.0.1`-ზეა. **არ გახსნათ ეს გარემო საერთო ქსელში, ტუნელში ან reverse proxy-ის უკან და რეალური პაროლი აქ არ შეიყვანოთ.** ლეპტოპზე წარმატებული ცდა production მზადყოფნას არ ნიშნავს.

თუ გაშვება ვერ დასრულდა, გამოიყენეთ [IT-ის დიაგნოსტიკის ცხრილი](IT_OPERATIONS_RUNBOOK_KA.md#პრობლემების-მოძიება). დეველოპერის ალტერნატიული `run-local.sh` ციკლი აღწერილია [პროექტის სამუშაო წესებში](../AGENTS.md#commands).
