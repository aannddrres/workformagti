# AI-ბრაუზერის სატესტო პრომპტი #3 — იერარქია, ექსპორტი, შესაბამისობა

პირველმა ტესტმა როლები შეამოწმა, მეორემ — მიზეზ-შედეგობრივი ჯაჭვები.
ეს მესამე სამ ადგილს ამოწმებს, რომელსაც აქამდე არავინ შეხებია და სამივეს
მონაცემთა გაჟონვის შედეგი აქვს.

**რატომ ეს სამი:**

- **მენეჯერების იერარქია** — კოდში ჩაწერილია, რომ კითხვას „ვინ ეკუთვნის
  მენეჯერს" ადრე ხუთი სხვადასხვა ადგილი პასუხობდა დამოუკიდებლად.
- **ექსპორტი** — აქვს ჩაწერილი ისტორია (SEC-02): ერთ დროს **ყველა მენეჯერს
  შეეძლო ჩამოეტვირთა სრული 602-კაციანი სია**. გასწორდა, მაგრამ ბრაუზერით
  არასდროს გადამოწმებულა. ბაზაში დღემდე **ნული** დასრულებული ექსპორტია.
- **ქვიზის კარიბჭე** — შესაბამისობის გული; არასწორი პასუხი ნამდვილად
  ბლოკავს თუ არა გაცნობას, არავის უცდია.

ფაილის ატვირთვა ამ სიაში არ არის: შემოწმებულია ცალკე და მუშაობს
(გადარქმეული `.exe` და ტექსტი 415-ით უარყოფილია).

ქვემოთ, ხაზებს შორის მოცემული ტექსტი დააკოპირე AI-ბრაუზერში.

# რაუნდი A — მენეჯერის ხედვის საზღვარი

წესი: **მშობელი დეპარტამენტის მენეჯერი ხედავს მთელ თავის ხეს; ქვეჯგუფის
მენეჯერი — მხოლოდ თავის ჯგუფს.**

„მენეჯერი" ღილაკი შედის ანგარიშით, რომლის დეპარტამენტია `ტექნიკური` —
ანუ **მშობელი დონე**.

**A1.** შედი **მენეჯერად**. გახსენი „გუნდის მდგომარეობა".
- ჩაიწერე **ჯამური რაოდენობა** (რამდენ ადამიანს ხედავს)
- ჩაიწერე **რომელი ჯგუფები ჩანს** (მოსალოდნელია ჯგუფი 01-დან 05-მდე)
- ✅ მოსალოდნელია დაახლოებით **195** ოპერატორი
- ❌ თუ **602**-ს ხედავს — მთელ კომპანიას ხედავს, ეს კრიტიკული ხარვეზია

**A2.** ახლა შევამოწმოთ საპირისპირო მხარე. შედი **სისტემურ ადმინად** →
„მომხმარებლები და წვდომა" → იპოვე `manager@magti.ge` → შეუცვალე
დეპარტამენტი `ტექნიკური`-დან **`ტექნიკური — ჯგუფი 02`**-ზე და შეინახე.
- ჩაწერე, გამოვიდა თუ არა შენახვა

**A3.** შედი **მენეჯერად** ხელახლა. გახსენი „გუნდის მდგომარეობა".
- ✅ სია უნდა **შევიწროვდეს** დაახლოებით **39** ოპერატორამდე
- ✅ მხოლოდ ჯგუფი 02 უნდა ჩანდეს, სხვა ჯგუფები არა
- ❌ თუ ისევ 195-ს ან 602-ს ხედავს — ქვეჯგუფის შეზღუდვა არ მუშაობს

**A4.** დააბრუნე დეპარტამენტი უკან `ტექნიკური`-ზე. გადაამოწმე, რომ
მენეჯერი ისევ მთელ ხეს ხედავს (~195).

**ეს რაუნდი ორივე მიმართულებას ამოწმებს:** ხომ არ ხედავს მეტს ვიდრე
უნდა (A1, A3), და ხომ არ ხედავს ნაკლებს ვიდრე უნდა (A4). ორივე ბაგია.

# რაუნდი B — ექსპორტი ბოლომდე

აქამდე მხოლოდ ის შემოწმებულა, რომ ექსპორტი „იწყება". არასდროს უნახავთ
**რა წერია გამოსულ ფაილში**. სწორედ იქ იმალება გაჟონვა.

**B1. მენეჯერის ექსპორტი — ყველაზე მნიშვნელოვანი ნაბიჯი.**

შედი **მენეჯერად** (დეპარტამენტი `ტექნიკური`). იპოვე ექსპორტის ღილაკი —
სავარაუდოდ „გუნდის მდგომარეობა" გვერდზეა (PDF ან ცხრილის ჩამოტვირთვა).
- ჩამოტვირთე ფაილი
- **გახსენი და დათვალე რამდენი ადამიანია შიგნით**

✅ **სწორია:** დაახლოებით **195–200** ჩანაწერი, ყველა `ტექნიკური`-დან.

❌ **კრიტიკული ხარვეზი:** თუ ფაილში **602** ჩანაწერია, ან სხვა
დეპარტამენტების ხალხი (`ოფისი`, `საინფორმაციო`) გვხვდება — მენეჯერმა
მთელი კომპანიის პერსონალური მონაცემები ჩამოტვირთა. დაწერე პირველ ადგილას
და მიუთითე რამდენი ჩანაწერია და რომელი დეპარტამენტები ნახე.

თუ ფაილს ვერ ხსნი, მაინც ჩაწერე მისი **ზომა და სახელი** — 602-კაციანი
ფაილი შესამჩნევად დიდი იქნება 200-კაციანზე.

**B2. ადმინის ექსპორტი.** შედი **სისტემურ ადმინად** → „მონაცემების
ექსპორტი". გაუშვი ექსპორტი.
- დავალება შეიქმნა? სტატუსი ჩანს (მუშავდება / დასრულდა / ჩავარდა)?
- **დაელოდე დასრულებას.** ჩამოტვირთვის ბმული გაჩნდა?
- ჩამოტვირთე. ფაილი იხსნება? დაზიანებული ხომ არაა?
- რამდენი ჩანაწერია? (ადმინისთვის 602-იც ნორმალურია — მას უფლება აქვს)

**B3. ფორმატები.** თუ რამდენიმე ფორმატია (CSV / XLSX / PDF), სცადე
თითოეული და ჩაწერე რომელი მუშაობს და რომელი არა.
- განსაკუთრებით PDF: **ქართული ასოები სწორად ჩანს თუ კვადრატებია?**
  (ეს ცნობილი სარისკო ადგილია — PDF-ს ქართული შრიფტი სჭირდება)

**B4. უფლება.** შედი **კონტენტ-ადმინად** და სცადე ექსპორტის გვერდზე
მოხვედრა (`/admin/exports` მისამართით).
- უარი უნდა მიიღო. ჩაწერე რა მოხდა.
