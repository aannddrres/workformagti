## 2. ძებნის ხარისხი

26 რეალურ ოპერატორულ კითხვაზე ძებნა **კარგად მუშაობს**: როუმინგი,
ტარიფი, ინტერნეტი, VPN, IPTV, ჰოსტინგი, დომენი, GPON, მობილური — ყველა
რელევანტურ შედეგს აბრუნებს; Latin-ტერმინები რეგისტრ-დამოუკიდებელია
(VPN=vpn); ნაწილობრივი სიტყვა და ირგვლივი ჰარეები მუშაობს.

**S-1 (კოდის ხარვეზი — გასწორდა).** ბოლოში `?` ან `!` ძებნას სრულად
ანულებდა:

| კითხვა | ადრე | ახლა (fix-ის შემდეგ) |
|---|---|---|
| `ინტერნეტი` | 48 | 48 |
| `ინტერნეტი?` | **0** ❌ | 48 ✅ |
| `ტარიფი!` | **0** ❌ | 27 ✅ |
| `VPN?` | **0** ❌ | 1 ✅ |

**ფესვი:** query trigram-ებად იშლებოდა პუნქტუაციის მოცილების გარეშე
(`SearchQueryService.splitWords`), ამიტომ `ინტერნეტი?`-დან ჩნდებოდა
trigram `ტი?`, რომელიც არცერთ სტატიაშია არაა → 0 კანდიდატი. **იგივე ქცევა
Python-ორიგინალშიც იყო** — ესე იგი ძველი პროდუქტ-ხარვეზი, არა პორტის
რეგრესია. **Fix:** `splitWords` ახლა თითო სიტყვას კიდეებიდან პუნქტუაციას
აშორებს (შიდა სიმბოლოები რჩება — „Wi-Fi" ხელუხლებელია). ტესტი:
`SearchQueryServiceSplitWordsTest`.

**S-2 (კონტენტ-ხარვეზი).** `ნომრის გადმოტანა` → **0**, თუმცა `პორტირება`
→ 7. სიტყვა „გადმოტანა" **არცერთ სტატიაში არ არის** — პორტირების მასალა
მხოლოდ ტერმინ „პორტირებას" შეიცავს. ოპერატორი, ვინც ბუნებრივად წერს
„ნომრის გადმოტანა", ვერაფერს პოულობს. გამოსავალი **რედაქტორისაა** — მასალას
საერთო სინონიმები/ტეგები უნდა დაემატოს. (ძებნა AND-ლოგიკითაა — ყველა სიტყვა
უნდა დაემთხვეს; ეს გააზრებული დიზაინია, არა ხარვეზი.)

## 3. სასიცოცხლო ციკლის კიდეები

**L-1 (კოდის ხარვეზი — გასწორდა).** ცალკე create/update **უაზრო
სტატუსს იღებდა**: `PUT` `status="banana"` → 200, ინახებოდა. და რადგან
ოპერატორისთვის მხოლოდ ზუსტი „published" ჩანს, უცნობი სტატუსი სტატიას
**ჩუმად მალავდა** — შეცდომა არ ჩნდებოდა. `bulk-status` endpoint უკვე
ამოწმებდა (`@Pattern`), ცალკე გზა — არა (`ArticleRequest.status` უბრალო
String-ი). **Fix:** იგივე `@Pattern` `ArticleRequest.status`-ს
(`draft|published|scheduled|archived`; null/ცარიელი → „draft" ისევ
ნაგულისხმევია). ტესტი: `ArticleRequestStatusValidationTest`.
