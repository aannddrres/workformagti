# აღმოჩენები

## F-1 · `/uploads/{ფაილი}` — ობიექტზე მიბმული უფლება არ მოწმდება

**სიმძიმე: P1** · **მატრიცა: WS2-04 (`Fail`)** · **გადაწყვეტილება: `DEC-P01`**

**რა ვნახე.** `uat.operator1` (ოფისი — ჯგუფი 01) ჩამოტვირთა სურათი, რომელიც
სტატია #32-ის შიგთავსშია — სტატიისა, რომელიც **ტექნიკურზეა** მიმართული და
რომელზეც იმავე მომხმარებელს `GET /api/articles/32` **404**-ს აძლევს.

```
GET /api/articles/32        -> 404   (სტატია დაცულია)
GET /uploads/1446e643...png -> 200   (მისი სურათი — არა)
                               image/png, 51 606 ბაიტი, ნამდვილი PNG
```

**რა მუშაობს:** ავთენტიფიკაცია მოწმდება — cookie-ს გარეშე **401**.

**რა არ მუშაობს:** ავტორიზაცია არ მოწმდება. ნებისმიერი შესული თანამშრომელი
წვდება ნებისმიერ ფაილს, თუ სახელი იცის.

**რამდენად რეალურია.** ფაილის სახელი 64-სიმბოლოიანი hex-ია — გამოცნობა
პრაქტიკულად შეუძლებელია. ე.ი. საჭიროა სახელის **ცოდნა**, რაც ჩვეულებრივ
სტატიის ნახვას ნიშნავს. მაგრამ სახელი ჩნდება: სტატიის HTML-ში, ბრაუზერის
ისტორიაში, გაზიარებულ ბმულში.

**ეს ახალი აღმოჩენა არ არის** — მატრიცაში WS2-04 უკვე `Fail`-ია. ღირებულება
ისაა, რომ ახლა **ზუსტად ვიცით რა იჟონება**: სტატიების შიგთავსის სურათები,
სრული ხარისხით, სხვა დეპარტამენტის თანამშრომლისთვის.

**რას საჭიროებს:** `DEC-P01` პროდუქტის გადაწყვეტილებაა — ფაილზე წვდომა
მშობელი სტატიის აუდიტორიას უნდა მიჰყვეს თუ არა. კოდით არ იხურება, სანამ
პოლიტიკა არ დაზუსტდება.

**რას ნიშნავს პრაქტიკულად.** თუ პროცედურა შეიცვალა, მენეჯერის დაფა
თანამშრომელს **შესაბამისად** აჩვენებს — თუმცა მან ახალი რედაქცია არ
უნახავს. ანუ ანგარიშგება რეალურზე უკეთეს სურათს აჩვენებს.

**ორივე ქცევა დასაცავია.** „დადასტურება ისტორიული ფაქტია, არ იშლება" —
სამართლიანია. „ცვლილების შემდეგ ხელახლა უნდა გაეცნოს" — ასევე. **მონაცემები

დარდება.
