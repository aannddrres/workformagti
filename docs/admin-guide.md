# მაგთი — შიდა საინფორმაციო პორტალი

## ადმინისტრატორის სახელმძღვანელო

ეს დოკუმენტი მოკლედ აღწერს ადმინისტრატორის (system_admin / content_admin)
ყოველდღიურ ოპერაციებს. ტექნიკური მხარდაჭერისთვის იხილეთ `README.md`.

## 1. როლები და უფლებები

| როლი                 | რას აკეთებს                                                                                                             |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **operator**         | სტატიების კითხვა, ძებნა, რჩეულებში დამატება, სავალდებულო წაკითხვის დადასტურება.                                         |
| **manager**          | „გუნდის სტატისტიკა" გვერდი → დეპარტამენტის თანამშრომლების წაკითხვის პროგრესი, შეტყობინებების გაგზავნა.                  |
| **content_admin**    | სტატიების / სიახლეების / ვიდეოების / კატეგორიების შექმნა, რედაქტირება, დაგეგმვა და არქივი.                           |
| **admin** (სისტემის) | ყველაფერი + მომხმარებლების მართვა, აუდიტ ლოგი, ექსპორტი (CSV/XLSX), broadcast.                                          |

> **მნიშვნელოვანი:** ყველა მნიშვნელოვანი მოქმედება ჩაიწერება აუდიტ ლოგში
> (`Admin → აუდიტ ლოგი`). ამ ლოგი ნახულობს მხოლოდ სისტემის ადმინი.

## 2. სტატიის შექმნა (content_admin)

1. `ჩემი სამუშაო რიგი → კონტენტის მართვა → + სტატია`
2. შეიყვანე სათაური, შინაარსი, კატეგორია და სამიზნე დეპარტამენტი.
3. სტატუსი:
   - **Published** — მაშინვე ჩანს.
   - **Draft** — დრაფტი, არ ჩანს ოპერატორებთან.
   - **Scheduled** — ავტომატურად გამოქვეყნდება მითითებულ დროზე.
4. სავალდებულო წაკითხვა → ჩართე checkbox-ი + დადე ვადა.
5. **მნიშვნელოვანი ცვლილება (2026):** სავალდებულო წაკითხვის ფლაგი ახლა მუშაობს
   **არსებული სტატიის რედაქტირებისასაც** — ან აანთებ ჩექბოქსს და ვადას, ან
   აქრობ checkbox-ს რომ ფლაგი წაიშალოს.

### „აქტუალურია" ბანერი

თუ სტატია 6 თვეზე ძველია, ოპერატორი დაინახავს გაფრთხილებას:

- 180 დღე → ყვითელი („გადამოწმება"),
- 270 დღე → ნარინჯისფერი („ხელმძღვანელის თანხმობა"),
- 365 დღე → წითელი („არ გამოიყენო").

ადმინი ხედავს „აქტუალურია" ღილაკს — დააჭერ, თარიღი განახლდება.

### „ხარვეზის რეპორტი" workflow

ოპერატორი სტატიის შიგნით აჭერს „ხარვეზის რეპორტი" → ჩანაწერი ჩნდება
`Admin → კონტენტის მართვა → ხარვეზების რეპორტები` ცხრილში.
სტატუსები:

- **ღია (open)** — ახალი მოხსენება.
- **მოგვარდა (resolved)** — ადმინმა გაასწორა და ღილაკით დახურა.
- **უარყოფილია (rejected)** — არასწორი მოხსენება.

## 3. სიახლის შექმნა (content_admin)

`Admin → კონტენტის მართვა → + სიახლე`

ახალი (2026):

- სიახლეებზე ახლა შესაძლებელია **ფაილის მიმაგრება** (PDF, სურათი, doc).
- სიახლეებს აქვს **ვერსიების ისტორია** — `🕘 ისტორია` ღილაკი
  ცხრილში → შეგიძლია წინა ვერსიის აღდგენა (ანალოგი სტატიების).
- სავალდებულო ფლაგი მუშაობს ისევე როგორც სტატიებზე (create + edit).

---

## 4. კატეგორიების მართვა (content_admin)

`Admin → კატეგორიები`

- **ძირითადი კატეგორია**: მშობელი ცარიელი დატოვე.
- **ქვე-კატეგორია**: მშობელში აირჩიე ძირითადი კატეგორია → ცოდნის ბაზის
  ფილტრში გამოჩნდება indented სახით (`└ ქვე-კატეგორიის სახელი`).
- ცოდნის ბაზის **ბენტო-კარდები** ახლა გენერირდება დინამიურად — ახალი ძირითადი
  კატეგორია ავტომატურად ჩნდება.

---

## 5. მომხმარებლების მართვა (system_admin)

`Admin → მომხმარებლების მართვა (RBAC)`

- **ახალი მომხმარებლის შექმნა**: ღილაკი `+ ახალი მომხმარებელი`.
  - დროებითი პაროლი მინიმუმ 8 სიმბოლო, შეიცავდეს ციფრს, დიდ + პატარა ასოს.
  - მომხმარებელი პროფილში (პარამეტრები → პაროლის შეცვლა) უნდა შეცვალოს.
- **როლის შეცვლა**: ცხრილში → role select.
- **გათიშვა/გააქტიურება**: ცხრილში → status toggle.
  ადმინი თავის ანგარიშს ვერ გათიშავს (404).

### ტესტირების რეჟიმი (dev only)

ფაილში `security.py` არსებობს `TEST_EMAILS` სია — ამ ანგარიშებზე ნებისმიერი
პაროლი მუშაობს, თუ DB SQLite-ია. ეს მხოლოდ ლოკალური დეველოპმენტისთვისაა,
**production-ში არ უნდა იყოს ჩართული**.

## 7. ექსპორტი

`Admin → მთავარი → CSV / XLSX` (მარჯვენა ზედა)

- **CSV** — წაკითხვის სტატუსები (compliance audit).
- **XLSX** — იგივე მონაცემები Excel-ისთვის (ფერადი header, ავტო-სიგრძე).
  გადახდევინებს `pip install openpyxl`-ის.

## 8. Backup / Restore

ფაილი `backup.py` აარქივებს ლოკალურ SQLite ბაზას **და `uploads/` დირექტორიას**
ერთ ZIP არქივში `backups/` საქაღალდეში.

```bash
# ერთჯერადი backup-ის გაკეთება
python backup.py

# არსებული backup-ების ნახვა
python backup.py --list

# კონკრეტული backup-იდან აღდგენა (interactive confirm)
python backup.py --restore ./backups/magti_portal_20260613_020000.db
```

### ავტომატური ყოველდღიური backup

**Linux (cron):**

```cron
0 2 * * * cd /opt/magti && /opt/magti/.venv/bin/python backup.py
```

**Windows (Task Scheduler):**

```cmd
schtasks /Create /SC DAILY /TN "MagtiBackup" /TR "python C:\path\to\backup.py" /ST 02:00
```

PostgreSQL-ისთვის სკრიპტი ბეჭდავს `pg_dump`-ის სწორ ბრძანებას.
