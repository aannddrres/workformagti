# წარმოებისთვის მზადყოფნის შემოწმებები — სახელმძღვანელო

ეს საქაღალდე ინახავს შემოწმებებს, რომლებიც 2026-10-03-ის QA რაუნდში
(მე-5) დაიწერა. მიზანი: იგივე შემოწმებები ნებისმიერ დროს თავიდან
გაეშვას. ლეპტოპზეც და IT-ის staging სერვერზეც.

ადრე ასეთი ხელსაწყოები დროებით საქაღალდეში ინახებოდა და იკარგებოდა.
ახლა ყველაფერი აქ არის.

## უსაფრთხოების წესები (ყოველთვის)

- შემოწმებები მუშაობს **მხოლოდ** დროებით სქემაზე `MAGTI_QA`. ეს წესი
  კოდშია ჩაწერილი: `qa_lib.py` უარს ამბობს Oracle-ის სხვა მომხმარებელზე,
  `127.0.0.1`-ის გარდა სხვა მისამართზე და პორტებზე 8080, 8081, 8082.
- `.env`, `.presentation.env`, `.uat.env` არ იკითხება.
- Docker-ის volume-ები არ იშლება.
- ამ ლეპტოპის Oracle 19.3 ბევრი სესიის ერთად გათიშვაზე ვარდება. ამიტომ
  ბაზის „გათიშვას“ `fault_proxy.py` აკეთებს: კავშირს წყვეტს, ბაზას არ
  ეხება.
- მისამართად `127.0.0.1` გამოიყენეთ და არა `localhost`.

## მომზადება

```bash
cd java-backend && ./mvnw.cmd -B -DskipTests package && cd ..
scripts/qa/qa-schema.sh create              # ცარიელი MAGTI_QA
scripts/qa/qa-backend.sh start 8090         # პორტალი MAGTI_QA-ზე
python scripts/qa/seed_world.py             # 122 სტატია, 600 ოპერატორი, აქტივობა
```

Windows-ზე ქართული ტექსტისთვის ჯერ: `export PYTHONUTF8=1`.

დასრულების შემდეგ:

```bash
scripts/qa/qa-backend.sh stop 8090
scripts/qa/qa-schema.sh drop
```

## IT-ის staging-ზე

სკრიპტები staging-ზეც გამოდგება. დაცვის წესები იქაც მოქმედებს:
მისამართი მხოლოდ `127.0.0.1`, სქემა მხოლოდ `MAGTI_QA`. ამიტომ staging-ის
პორტალი `kubectl port-forward`-ით მოიტანეთ ლოკალურ პორტზე (მაგ. 8090). ბაზა
`QA_DSN`-ით მიუთითეთ, პაროლი კი `ORACLE_DB_PASSWORD`-ით. staging-ზე ცალკე
`MAGTI_QA` სქემა უნდა შეიქმნას. რეალურ მონაცემზე ეს სკრიპტები არასდროს გაუშვათ: ზოგი მათგანი
ბაზაში თარიღებს ცვლის და აუდიტს აფუჭებს.
